# ONLYOFFICE Docs for Harbor

A [Harbor](https://github.com/carlosalaniz/harbor) app: [ONLYOFFICE Docs](https://www.onlyoffice.com/docs)
(Document Server 9.4.0.1, community edition), image pinned by digest, meant as the editor of a
Harbor Nextcloud through Nextcloud's `onlyoffice` connector app.

```
harbor/            the Harbor package
  manifest.yaml    endpoint (port 80), health (/healthcheck), storage claims, generated JWT secret
  compose.yaml     documentserver (ONLYOFFICE's all-in-one image)
  README.md        shown in Harbor's App Store: install, publish, connect Nextcloud
```

## Install

In Harbor: **App Store → Your own app → Git repository** with this repository's HTTPS URL and
branch `main` (or `harbor sources add https://github.com/carlosalaniz/harbor-onlyoffice --branch main`),
then install **ONLYOFFICE Docs**. Copy the JWT secret shown once at the end of the install, publish
the app under its own public domain, and point Nextcloud at it. The steps and `occ` commands are in
[harbor/README.md](harbor/README.md).

## How it runs

| Setting | Why |
|---|---|
| `JWT_ENABLED=true`, `JWT_HEADER=Authorization`, `JWT_SECRET` from Harbor | Nextcloud and the document server sign every request; the secret is generated by Harbor (32 bytes, hex) and shown once |
| `ALLOW_PRIVATE_IP_ADDRESS=true` | ONLYOFFICE refuses to download from private addresses by default; a Nextcloud whose public name resolves to a private address (split DNS, NAT hairpin, same Harbor) would fail to open files |
| `ALLOW_META_IP_ADDRESS=false` | Link-local / cloud-metadata addresses stay blocked |
| `WOPI_ENABLED=false` | Nextcloud's connector uses the editor API, not WOPI |

The image runs PostgreSQL, RabbitMQ and Redis inside the one container. PostgreSQL and the
document caches are kept in volumes; RabbitMQ and Redis only hold transient queues and are
recreated with the container. Nothing secret lives in this repository.
